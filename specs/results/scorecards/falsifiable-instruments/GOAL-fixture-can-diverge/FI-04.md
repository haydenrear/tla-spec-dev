## What FI-04 got wrong and corrected, before any cell was read

The first version of `divergence.py` compared **sets of verdicts across all rows**
and reported **four** divergences instead of one, because arm B contributed
`{KILLED, SURVIVED}` from two rows against arm A's `{KILLED}` from one —
conflating *"arm B has an extra row"* with *"the arms disagree"*. And it
attributed a composition pair's count to **both** halves, so `corpus-port-swap:real`
and `suite-real` looked reachable on three arms whose `:real` columns had all run
the same thing.

Both were analysis bugs in code FI-04 wrote in this ticket; **no measured cell
moved**, and the corrected tool reports **one** divergence rather than four. The
assertion was not weakened: `tests/test_fixture_can_diverge.py` feeds
`divergence.py` an input where it must still go
`CLAIMED_REACHABLE_BUT_UNDEMONSTRATED` and exit nonzero, which is R1 applied to
the analysis itself.

### What the merge broke — `FI-04-DF-04`

FI-02's instrument enumeration exists so that **nothing is silently omitted**,
and its completeness check is a **hardcoded list of ten paths** asserting
`required <= enumerated`. That catches a rename dropping a row. It cannot catch
an addition never made: a new instrument is not in `required`, so the subset
relation stays true. FI-04 ships `divergence.py` — it watches a subject,
produces a verdict, and returns nonzero on it, which is the registry's own
definition — and **FI-02's suite was fully green with it absent.**

Registered by hand during this reconcile with its already-shipped failing,
passing and **blind-spot** demonstrations; `demonstrate.py --only
divergence-reachability` reproduces all three. The declared blind spot is
FI-04's own: the comparable row is **declared** (`wired_by_default`), not
derived, so a mis-declared row produces a **wrong count rather than a refusal** —
the unsafe failure direction, and the same shape `FI-01-DF-04` recorded against
`PORT_REGION`.

`FI-04-DF-01` is marked **settled** against `501eacd`. Its summary is left
exactly as written: it describes the tree at `found_at_commit`, and editing a
finding to match the repair it caused is how a caught defect stops being visible.
