SO THE ARGUMENT-NAMING CHANGE CANNOT MOVE A COMMITTED ARTIFACT. It changes what
a FUTURE generation emits, on a model that declares an action marker, and only
for cases the negative pass produces.

The two models this repository generates negative corpora from, both measured:

  examples/distributed_history   declares a marker  -> 11 cases re-keyed, and
                                                       they now execute
  examples/validation/ab/QuotaLedger  declares NONE -> 118 cases byte-identical
                                                       (quota-ledger-corpus-unchanged.txt)

The scaffolders DO emit the marker -- scripts/scaffold_spec.py:208 and
scripts/onboard_program_model.py:150 both write
`lastInternalAction' = [name |-> ..., params |-> [<declared> |-> <formal>]]` --
so every project this toolchain scaffolds from here on gets negative cases whose
arguments its adapters can read. That is the fix's real reach and it is stated
here rather than claimed in a summary.
