Two independent findings confirmed while reproducing:
  * TLC searches the directory of the .tla it is handed and the TLA-Library
    system property. It does NOT search the current directory: running tlc2 from
    specs/program_model/ with an absolute path to the case module fails
    identically.
  * TLC 2.19 has no -lib flag (`tlc2 -help` lists none), so the search path can
    only be set as a JVM system property.

WHAT THE ERROR SAYS NOW WHEN A MODULE REALLY IS MISSING
-------------------------------------------------------
The hierarchy is resolved BEFORE the JVM starts, so this arrives instead of a
SANY stack (exit 1, nothing written, TLC never invoked):

ERROR: module Scenario_X EXTENDS NotHere, but NotHere.tla is in none of the
directories on the module search path:
    /private/tmp/rp03miss/specs/case_modules  (module)
  TLC resolves EXTENDS against the directory of the .tla it is given and the
  TLA-Library search path -- never against the current directory. Put
  NotHere.tla on the path with --module-path <dir containing NotHere.tla>, or
  move the module beside it. (If NotHere is a standard library module this
  toolchain does not know, add it to analyze_complexity.STANDARD_MODULES once
  verified.)

HOW
---
scripts/case_modules.py
  resolve_search_path()      resolves the EXTENDS closure over three kinds of
                             candidate directory, in precedence order: the
                             module's own directory, every --module-path, then
                             sibling directories that contain .tla files.
                             Ambiguity between two siblings is an ERROR naming
                             both, never a coin flip.
  tlc_environment()          sets -DTLA-Library=<path> via JAVA_TOOL_OPTIONS,
                             and ONLY when something resolved outside the
                             module's own directory, so the ordinary single-
                             directory case is byte-identical to before.
  resolve_manifest_path()    finds spec_manifest.yaml along the same path.
scripts/analyze_complexity.py
  resolve_module(search_path=...) -- the scanner reads the SAME path, so the
                             scan and the corpus cannot describe different files.
scripts/generate_cases_from_tlc_dump.py
  --module-path DIR (repeatable) for a view that is not a sibling; the search
  path is resolved before anything expensive runs.

Regression tests: tests/test_case_modules.py, the RP-03 block (11 tests),
including test_the_shipped_internal_fixture_generates_from_its_documented_location
which pins the ex4 layout itself.
