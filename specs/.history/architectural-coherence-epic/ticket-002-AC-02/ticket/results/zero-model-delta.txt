WHY IT IS ZERO
--------------
AC-01 already landed everything this ticket needs on the model side:

  * the `architecture_scan` variable, ranging over
    unknown | coherent | divergent | unmappable, and
  * the `AnalyzeArchitecture` action, which sets
    result' = CommandResult(TRUE, ...) unconditionally and merely records a
    verdict in that variable.

AC-02 supplies the CODE side of the same command. It adds no CLI command, no
new externally observable outcome, and no new state: `analyze architecture`
already existed and already recorded a value in `architecture_scan`. What
changed is which of the four values it can produce -- `coherent` and
`divergent` become reachable when `--code` and `--map` are supplied, where
before only `unmappable` was. The TLA+ variable's domain was authored to
include all four at AC-01 precisely so this ticket would not have to widen it.

Adding an action for the reflexion check would have modelled a FLAG of an
existing command as a separate program transition. The plan's
`semantic_model_rule` forbids exactly that class of addition, and the standing
objective would then have charged this ticket a state-space increase for a
distinction the program does not make.
