# RP-02 -- the audit now reports what the run measured (EV-02-DF-03)

`param_recovery_audit.md` was rendered from `param_recipes` alone: a reading of
the module's SYNTAX. Nothing in it had ever seen a case. So it could -- and did
-- print

    Every parameter of every action is recoverable from its state pair.

next to a corpus carrying no recovered argument at all. The sentence is
reachable whenever no parameter is statically UNRECOVERABLE, including the
vacuous case where the module declares no parameters anywhere.

## Case 1 -- `reminder_worker`: the vacuous universal, verbatim

Seven nullary actions, seven cases, and every argument the corpus carries comes
from the model's own `lastInternalAction` marker -- stated by the model, not
recovered by this module. The committed audit says:

```
| `ProcessRetryable` | *(none)* | n/a -- nullary action | - | - |

## Findings

Every parameter of every action is recoverable from its state pair.
```

The same recipes and the same 7 cases, through RP-02's audit:

```
**Model-declared, not recovered.** The corpus carries these arguments because the model states them in its own action marker. No mechanism in this module produced them and none is credited for them:

- `ProcessAccepted(scenario)` -- stated by the model on 1 of 1 cases
- `ProcessDuplicate(scenario)` -- stated by the model on 1 of 1 cases
- `ProcessEmpty(scenario)` -- stated by the model on 1 of 1 cases
- `ProcessNotDue(scenario)` -- stated by the model on 1 of 1 cases
- `ProcessPendingRetry(scenario)` -- stated by the model on 1 of 1 cases
- `ProcessPermanent(scenario)` -- stated by the model on 1 of 1 cases
- `ProcessRetryable(scenario)` -- stated by the model on 1 of 1 cases

This corpus exercises no parameterised action, so this module recovered nothing and makes no recoverability claim.
```

## Case 2 -- a PARTIALLY failing run, which is the ticket's own acceptance

Statically every parameter of the ex4 model is now recoverable. Feed the audit
a run in which recovery partly failed anyway, and it reports the failure per
class rather than the syntax:

```
# Action parameter recoverability audit

Generated by `scripts/infer_action_params.py` (MF-029, RP-02) from the
TLA+ module source. Every action label is listed, including the ones with
no parameters, so the audit is complete rather than selective.

**Measured over the corpus this run generated: 198 cases.**
The `Measured` column is the count from those cases, not a reading of
the syntax. Where the two disagree, the measurement is the finding.

| Action | Parameter | Mechanism | Source variable | Measured on this corpus | Fields no longer independently checkable | Observations the recovery consumed |
|---|---|---|---|---|---|---|
| `Accept` | `i` | set-membership | `inbox` (left), `accepted` (entered) | **PARTIAL -- 18 of 22 cases carry it** | - | which element entered `accepted`; which element left `inbox` |
| `Deliver` | `i` | set-membership | `queue` (left), `delivered` (entered) | recovered in 66 of 66 cases | - | which element entered `delivered`; which element left `queue` |
| `Enqueue` | `i` | set-membership | `queue` (entered) | **UNRECOVERABLE ON THIS CORPUS -- 0 of 110 cases carry it** | - | which element entered `queue` |
| `Fail` | `i` | set-membership | `delivered` (left), `failed` (entered) | *not exercised by this corpus (0 cases)* | - | which element entered `failed`; which element left `delivered` |
| `Record` | `i` | set-membership | `ledger` (entered) | *not exercised by this corpus (0 cases)* | - | which element entered `ledger` |

## Findings

**UNRECOVERABLE on this corpus.** These parameters were reached by a mechanism, and the mechanism recovered NOTHING on a single case. The class is UNRECOVERABLE for this run whatever the syntax promised:

- `Enqueue(i)` -- 0 of 110 cases carry an argument

**PARTIALLY recovered.** Some cases carry an argument and some do not:

- `Accept(i)` -- 18 of 22 cases carry an argument, 4 carry `UNCHECKED`

```

Note what did NOT happen: no case was dropped to make the numbers agree, and
`Fail` and `Record` are reported as *not exercised* rather than counted as
either a success or a failure.

## Case 3 -- no corpus at all

`python3 scripts/infer_action_params.py <module>.tla` has no corpus to measure,
so it now declares itself STATIC and makes no claim:

```

Generated by `scripts/infer_action_params.py` (MF-029, RP-02) from the
TLA+ module source. Every action label is listed, including the ones with
no parameters, so the audit is complete rather than selective.

**STATIC AUDIT -- NO CORPUS WAS MEASURED.** Every mechanism named below
is a claim about the module's syntax only. It is NOT evidence that any
generated case carries an argument; nothing here may be read as one.

| Action | Parameter | Mechanism | Source variable | Fields no longer independently checkable | Observations the recovery consumed |
|---|---|---|---|---|---|
...
## Findings

No corpus was measured, so this audit states NOTHING about how many cases carry an argument. Run the generator to obtain that number; a mechanism named above is not a recovered argument.

```
