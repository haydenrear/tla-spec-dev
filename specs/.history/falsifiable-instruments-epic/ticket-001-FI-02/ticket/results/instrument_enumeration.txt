INSTRUMENTS THAT CANNOT BE SHOWN TO FAIL, with the reason
------------------------------------------------------------------------------
  produced-code-instrument
      BY CONSTRUCTION AND ON PURPOSE, and this is the one row where that is the
correct answer rather than a defect. It is a THERMOMETER: it reports, refuses
nothing, gates nothing, and exits 0 on a tree that does not exist, a file that
does not parse and a file that is not UTF-8. `EXIT_OK = 0` is the only exit
constant in the file and `tests/test_code_complexity.py` asserts that against
the AST, not against prose. 'I could not measure this' is a completeness fact
printed with the path and the reason. The blind-spot row demonstrates the
inability rather than asserting it.

  suite-verification
      A PREDICTION DISAGREEMENT CANNOT MAKE IT RED. `verify_suite` prints
`*** DISAGREES ***` for a wrong prediction and then does not append it to
`problems`, and the function says so in its own closing disclaimer. Only two
conditions reach `problems`: a missing anchor tree, and a control run that is
already red on the UNMUTATED tree. So the one thing the mode is named for is
the one thing it cannot report, and every `predicted_suite` annotation in the
catalogue is unchecked prose. Filed as FI-02-DF-01.

  port-swap-driver
      NOT ON ITS EXIT CODE. `main()` ends `return 0` with no branch above it, so a
run that finds every control violated on every instrument, and a run that finds
none, are indistinguishable to any caller that reads the status. It has
ALREADY happened: `examples/validation/ab/eval/results/fi01/swap-reference_ports.json`
records PA-M14 as `control_red` and that run exited 0. Its printed verdict CAN
go red and does; nothing that consumes an exit code can see it. Filed as
FI-02-DF-02.

  source-citation-tripwire
      NOT WITHOUT BREAKING A SHIPPED FILE. Its predicate is written inline in a
pytest parametrised over a FIXED list resolved from the test file's own
location, so there is no root a fixture tree could be handed and no factored
function a demonstration could call. The only red input is a real citation, a
real manifest or a real YAML document broken on purpose in the tree every other
measurement in this epic reads. NOT REPAIRED HERE: refactoring a tripwire to be
demonstrable while it is watching the trees this ticket measures is the
forbidden half of the repair rule, and the honest move is to count it. Three
tripwires share this shape -- `test_source_citations.py`,
`test_spec_yaml_valid.py` and `test_port_declarations.py` -- and each is
counted separately rather than folded into one row.

DEMONSTRATED BLIND SPOTS -- a genuine break each one does NOT report
------------------------------------------------------------------------------
  effect-oracle
      a process.spawn is UNOBSERVABLE whatever a port declares, so any effect a child process performs is outside this oracle by construction -- the kill test must run outside the sandbox for exactly this reason, and says so on every run
  tla-complexity-descriptor
      a model 432x over its own declared state-space bound and 5x over its per-component variable bound: WARNINGS, and exit 0. There is no input that makes this instrument refuse on complexity, deliberately (MF-036, and CD-01: a tool that picks the boundary makes every edge legal by construction).
  produced-code-instrument
      a tree with a file that does not parse, a path that is not there, and a module 12 branches deep in every method: exit 0, every time. Nothing you can put in front of this instrument makes it refuse.
  catalogue-integrity
      it makes a MEASUREMENT catalogue's obligations of a SUPPLEMENT catalogue, so probing one control on one arm prints sixteen complaints that are all true of the wrong file, and it refuses every per-arm catalogue including two sealed ones
  control-decision-driver
      IT CANNOT MEASURE A PORTED TREE AT ALL. Its purge is keyed on ARM_MODULE_PREFIXES = ('quota_ledger',), so on a ported tree `domain` and `journal_file` stay cached and every mutant seeded in them runs against unmutated code: 15 of 15 false SURVIVED, no error, looking exactly like a clean measurement.
  port-swap-driver
      a red control changes nothing about the exit code, shown against the shipped source
  scorecard-audit
      OPEN and UNVERIFIED findings are printed and then not counted -- only VIOLATION increments the exit code, so a claim whose commit does not resolve, and a repair that declares neither verdicts_moved nor verdicts_unmeasurable, both leave a green audit
  blinding-sanitiser
      THE VERIFICATION IS VACUOUS AGAINST ITS OWN VOCABULARY. `This is ARM B, the hexagonal treatment arm. I was given the HEXAGONAL prompt by HP-02.` -- the exact sentence PA-06-DF-11 measured -- passes CLEAN, because the grep runs AFTER the substitutions and looks for very nearly the set they just removed. The instrument reports zero problems on the leak it was written to catch.
  thermometer-tripwire
      a consumer that reads a previously written complexity JSON and gates on it WITHOUT EVER NAMING THE INSTRUMENT is invisible -- and that is the route the one real reader in this repository takes, so the scan can never be relied on alone

Every declared demonstration reproduced.
