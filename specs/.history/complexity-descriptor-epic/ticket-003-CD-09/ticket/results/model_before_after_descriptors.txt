Reading
-------

The advisory-faithful delta is a distinct-state INCREASE at constant
variables, bound, actions, and depth. That is the expected shape: the removed
guard (`complexity_gate = "pass" \/ (fail /\ override)`) was a BLOCKING branch
the shipped program does not perform, so removing it EXPANDS the represented
behavior to what the program actually does -- spec-unit runs (and therefore
ticket advancement) are reachable while complexity_gate is still "unknown",
exactly as `tla-spec-dev run spec-unit-tests` behaves (it performs no
complexity check; the descriptor is advisory, MF-036/CD-01). The ticket brief
predicted a decrease; the measurement says otherwise, and the measurement
wins. There is NO generated-states drop at constant distinct states, so the
MF-020 red-flag pattern does not arise in this delta; the transition-level
diff is still recorded (transition_diff.md) and every edge change is
explained there.

The carried budget matters now: max_distinct_states stays at the negotiated
500,000 (rationale preserved verbatim in spec_manifest.yaml budgets block);
the after-model reaches 283,805 distinct states, 56.8% of that cap -- the
un-negotiated 50,000 default would false-fail this honest model.

Descriptor-visible structural effects:
- complexity_gate's row in the R/W matrix is now write-only (AnalyzeComplexity
  records it; no action reads it) -- the descriptor now shows the advisory
  verdict as an observable fact, not a control input.
- The variable-interaction clustering collapses from two components
  (C1: 6 vars / C2: complexity_gate, corpus_gate, effect_conformance) to one
  9-variable component, adding an advisory WARNING (9 > max_component_variables
  6) alongside the pre-existing 14 > max_component_actions 8. Q drops 0.012 ->
  0.000. This is honest: the gate-read edge that made C2 look separable was
  the withdrawn blocking coupling; without it the single-module baseline is
  what it always was, one component (the Internal/External split remains the
  recorded known_gap, MF-023 lineage).
- Justification linkage: every variable still linked (complexity_gate via
  TypeInvariant); invariant-coverage gaps unchanged (lastCommand, result).

TLC invariant sets: SpecUnitTestsRequireAnalyzedGate removed from the model,
MC.cfg, and MCsmall.cfg (it asserted the withdrawn blocking behavior and is
false of the advisory program; tombstone comment in the module). All 13
remaining invariants green in both runs (tlc_before.txt, tlc_current.txt).
