# ex4 run 5 — determinism and replay, round 2 (A3-P1..P4, DP-6)

Run date 2026-07-30, EV-03. **Mechanical run: no agent.** Run 5 is not a repeat
of run 4's commands against run 4's artefacts — it is the whole 19-mutant matrix
re-executed against a **second, independently generated corpus** (`gen2`), so a
difference between the runs could come from either generation or execution.

DP-6 is binding: no determinism claim in this ticket rests on one execution.

## The thing that must not be misread

**RP-02 and RP-03 both changed generated content on purpose.** The corpus
fingerprint moved:

| | round 1 | round 2 |
|---|---|---|
| `cases.py` sha256 (view corpus) | `33e07e0de5360fae105466c0ea7869a4face3c3dfa116de63452888c78be6f97` | `944189052623960aea36dd9277c9d714c76ce18d584a67d8ed5b498170648f2e` |
| cases carrying a real argument | 0 of 330 (`params={'i': UNCHECKED}`) | **330 of 330** (165 × `i1`, 165 × `i2`) |

That is a **recorded content change**, not a determinism failure, and the
fixture's own `evidence/corpus_fingerprint.txt` carries both values with the
reason. The round-2 value reproduces RP-02's recorded fingerprint **exactly**,
in a different worktree and a different output directory. What must hold in
round 2 is internal stability across two runs, and it does.

## A3-P2 — the execution matrix, run 4 vs run 5

**38 executions per run**: control × 2 arms, `seeded_faults.toml` 6 mutants × 2
arms, the 12-mutant catalogue × 2 arms. Comparison is over exit code, the runner's
own failure count, the set of failing case names, and sha256 of stdout after
normalizing only the corpus path and the per-run temp directory.

| | round 1 | round 2 |
|---|---|---|
| executions compared | 14 | **38** |
| byte-identical | 14 | **38** |
| differing | 0 | **0** |
| of which FAILING executions | 12 | **24** |

Machine-readable, every row with both digests: `artifacts/run_comparison.json`.
The pytest column (12 mutants) is identical across runs as well.

**A3-P2 PASS**, and on 2.7× the executions round 1 compared. A corpus that is
deterministic only when it passes is not a deterministic corpus; 24 of the 38
compared executions are failing ones.

## A3-P3 — failure replay

Method unchanged from round 1 (`artifacts/replay.py`, the round-1 harness, run
verbatim): reseed the fault, take the **first `EFFECT_FUZZ_FAILURE` record**
from the batch log, run its `replay` field **verbatim**, twice.

| mutant | arm | case | replay exit ×2 | reproduces the batch failure? | two replays identical? |
|---|---|---|---|---|---|
| F1 wrong value | A | `case_0020_record` | 1 / 1 | **yes** | **yes** |
| F3 off-by-one durable | B | `case_0020_record` | 1 / 1 | **yes** | **yes** |
| F4 wrong status | A | `case_0001_accept` | 1 / 1 | **yes** | **yes** |

Same three fault classes, same two arms, **same case names as round 1** — which
is itself a result: RP-02 changed what every case carries and did not change
which case fails first. **A3-P3 PASS.**

**A3-P4** — no difference of any size was found anywhere in the aim-3 matrix.
Recorded so that the day it stops being true is visible.

## Interpreter note (EV-02-DF-05)

Round 1 got a cross-interpreter data point by accident (3.9.6 vs 3.14.6 under
`timeout(1)`). Round 2 deliberately pins ONE interpreter for every measurement,
because the accident is the finding: no `python3` on this machine's PATH carries
`yaml`, `pytest` and `tomllib` together. That means round 2 **loses** round 1's
cross-interpreter evidence and gains a controlled one. Both are worth having;
neither is stated as the other. EV-02-DF-05 is re-scored **still open** in
`../ex4-run4/scoring.md`.
