# ex4 run 2 — the two-run rule and aim 3, scored against PREDICTIONS.md (A3-P1..P4, DP-6)

Run date 2026-07-27, EV-02. **Mechanical run: no agent.** Run 2 is not a repeat
of run 1's commands against run 1's artefacts — it is the whole aim-1 matrix
re-executed against a **second, independently generated corpus** (`gen2`), so a
difference between the runs could come from either generation or execution.

DP-6 is binding: no determinism claim in this ticket rests on one execution.

## Independent regeneration (the generation control)

`gen2` was generated by a second full run of `generate_cases_from_tlc_dump.py`
over the same model, into a different output directory, **under a different
Python interpreter than `gen1`** (3.14.6 vs 3.9.6 — see the note at the end).

```
diff -r gen1/spec-unit/pipeline_cases gen2/spec-unit/pipeline_cases
  -> cases.py, types.py, validators.py, doubles.py, __init__.py  IDENTICAL
  -> case_coverage.json differs in exactly one field: "source" (the output path)
```

`cases.py` sha256 `33e07e0de5360fae105466c0ea7869a4face3c3dfa116de63452888c78be6f97`
in both, and equal to the value EV-01 recorded. **A3-P1 PASS**, now with a
cross-interpreter data point EV-01 did not have.

## A3-P3 — failure replay. The half EV-01 could not do.

EV-01 observed replay commands being emitted and did not run a mutant, so A3-P3
was a **prediction, not a measurement**. It is a measurement now.

Method: reseed the fault, take the **first `EFFECT_FUZZ_FAILURE` record** from
the batch log, run its `replay` field **verbatim** — twice.

| mutant | arm | case | replay exit ×2 | reproduces the batch failure? | two replays identical? |
|---|---|---|---|---|---|
| F1 wrong value | A | `case_0020_record` | 1 / 1 | **yes** — same error string, byte-for-byte | **yes** |
| F3 off-by-one durable | B | `case_0020_record` | 1 / 1 | **yes** (`DETECTOR[provider_content_assertion]`) | **yes** |
| F4 wrong status | A | `case_0001_accept` | 1 / 1 | **yes** | **yes** |

Three replays across both arms and three fault classes, each executed twice, all
six reproducing the originating failure exactly. **A3-P3 PASS.** The replay
command is self-contained: it carries `--seed`, `--fuzz-runs 1`,
`--fuzz-iteration`, `--case`, the mapping, and all three `--import-root`s, and
required no reconstruction.

**A3-P4** — no difference of any size was found anywhere in the aim-3 matrix.
Recorded so that the day it stops being true is visible.

## The one non-determinism this ticket did find, and it is not the toolchain's

`gen1` was generated with `/usr/bin/python3` (3.9.6) and `gen2` with
`/opt/homebrew/bin/python3` (3.14.6). This was not planned: on this machine
`python3` under `timeout(1)` resolves to a different interpreter than `python3`
in an interactive shell. It produced a **stronger** result (the fingerprint is
stable across a five-minor-version interpreter gap), but it is worth recording
as an environment hazard for anyone reproducing these numbers, and it matches
blind run B's independent finding #6 that no `python3` on PATH carries both
`yaml` and `pytest`. **EV-02-DF-05, filed not fixed:** neither the fixture README
nor the validation README states an interpreter requirement, and the commands
they publish are interpreter-ambiguous.
